# OPENING READING LIST — BY ROLE

Read by the `session-start` skill (step 2). One reading per line, in order. What has already been read by the Owner's opening prompt is not read again: checked, completed only.

## Pilot

**The first line of prose of the first answer is the verdict**: `READY` or `NOT-READY (<motif>)`. Nothing before. An anomaly found during the opening is the **reason** for the `NOT-READY`, never a paragraph before it (Mission 154, faults measured in report 153: case 1 and case 5).

Chain of pointers, in this order, each link naming the next, none held from memory: instructions of the Project (outside the repository, Owner gesture) → the Vault's charter `rules/RULES-2026-08-23-224706-role-charter-and-session-determination.md` → this file → digest → handoff → refs.

Opening reading reduced to the capped digest (Mission 121), budget aligned on the entry chain (Mission 136): **eight filesystem calls** before the READY/NOT-READY verdict when the digest is fresh, **ten at worst**, counted one by one — (1) authorized directories of the MCP server, (2) `VAULT-ROOT.md` at the root, (3) the Vault's `CLAUDE.md`, (4) the charter, (5) this file and the digest in a single `read_multiple_files`, (6) the canary (a `get_file_info` on the digest), (7) the freshness measurement (a `get_file_info` on `state/journal.md`), (8) the handoff that the digest names and the four Git refs plus the two `packed-refs` (six paths) in a single `read_multiple_files` — the order digest → handoff → refs of Decision 140714 point 2 is kept; a ninth call — the journal in `tail 5` — only if the digest is stale, a tenth — `tail 30` — only if the five lines are not enough (see the freshness test); nothing else. What the opening prompt has already had read counts within the eight and is not read again. Tool searches are counted separately (Decision 145256). The verdict is the **first line of prose** of the opening answer, exact word `READY` or `NOT-READY (<motif mesuré>)`; the `[role: …]` announcement follows. After the state, the "Opening / budget" [« Ouverture / budget »] rubric (Decision 140714, point 6): tool calls counted one by one; bytes reported — only `get_file_info` returns a size, so the digest (canary) and the journal (freshness measurement) carry theirs, the other readings are listed by name with the mention "size not reported" [« taille non rapportée »], never estimated; tool searches run and schemas loaded. Every state value reported carries its status: `VERIFIED` (read on disk in this session, source named), `DECLARED` (copied from the digest or the handoff, with the timestamp of the source), `ANOMALY` (disagreement between two sources, named as such).

1. `<projet>/state/DIGEST.md`, in full — capped opening digest, generated by the Vault's `tools/build-digest.sh` (8,000 bytes, fail-closed). **`<projet>` is named by the Project instructions** — first link of the chain above — and is never searched for: no exploratory `search_files` to locate a digest. If nothing names the project, the verdict is `NOT-READY (projet non nommé)` [project not named], not a search (Mission 156, only off-list call measured in run 155 of case 1). **Freshness test** (Mission 119, transposed to the digest by Mission 121, made measurable without reading by Mission 136): a `get_file_info` on `state/journal.md` returns its last-modification timestamp; if it is **later** than the digest's line « Dernière entrée journal : \<horodatage\> » ["Last journal entry: <timestamp>"], the digest is stale; equal or earlier, it is fresh. Reference measurement (2026-09-04): modification 16:16:19 = last dated line 16:16:19, digest 16:11:47 — stale by one line, that of the delegated push, which is the ordinary case after any pushed close. A recent checkout or clone may return a "stale" wrongly (file timestamp reset); never a "fresh" wrongly — the direction of the error is safe. If it is stale: say so as it is in the five-line state, read the journal in `tail 5` in its place (lines capped at 300 characters since Mission 123), `tail 30` only if the oldest of the five is still later than the digest's line, and do not regenerate it yourself — regeneration (the Vault's `tools/build-digest.sh <projet>`, argument = folder of the project) is an Executor gesture prescribed by a Mission. The READY/NOT-READY verdict does not depend on freshness.
2. The last handoff of `<projet>/handoffs/`, the one the digest names under « Dernier handoff » ["Last handoff"] (or that the opening prompt names), in full — the resume queue.
3. Git refs of the two repositories (`.git/refs/heads/main`, `.git/refs/remotes/origin/main`) and `.git/packed-refs` of the two repositories, six paths in the same `read_multiple_files` as the handoff — the gap between the disk and what is expected. A ref whose `refs/…` file is absent is not an anomaly: Git has packed it; its value is the SHA of the `packed-refs` line whose name ends with that ref; if the `refs/…` file exists, it prevails (more recent). A ref not found in either source carries `ANOMALY`. Each ref carries `VERIFIED`; a ref copied from the digest for lack of reading carries `DECLARED`. Refs and digest in disagreement = named `ANOMALY` — a closing commit later than the digest is the ordinary case, to be said as it is. The working tree (`git status --porcelain`) is never measurable from the Pilot surface: always `DECLARED`, value and timestamp from the digest, never "clean" deduced from the equality of the refs.

An index is read by `tail` or by searching for a line, never in full; the opening digest remains the only full reading prescribed (Decision 124647, point 6). A voluminous folder carries a live `index.md` and frozen `index-archive-*.md` files: the archive is read only on request.

Parsimony (Decision 140714): the Pilot's own artefact — filed during the session, present in the context — is never read again in full; `edit_file` in `dryRun` is a measurement in the sense of Decision 212009 (the failure on an absent string is the measurement, the diff is the proof), `head` or `tail` otherwise. A mini-prompt is issued once: any resume says "snippet unchanged" or reissues the single modified rubric, named. One tool search per family, phrased on the tool's description (verb and object: « search memories », « write file ») — the search index carries the descriptions, not the names (measurement 132-A); a second search is allowed, and counted in the budget, if the first does not bring up the tool sought.

### Memory — the only source of state is the journal

No external memory bank is wired into this AIOS (Decision 113850, removal measured in Mission 147). Every state write goes through the journal (`append-journal.sh`, Executor) — a model's memory is never a source of state.

### Before any filing

Before writing a Mission: open the `ecriture-de-mission` skill and run `mission-checklist.md`, line by line, before any filing. File through the DRAFT pattern (`ecriture-de-mission/SKILL.md` §6): never a `MISSION-…` file written directly. No mini-prompt is issued without the list having been run (Mission 151).

Before any search for a file or a term in the Vault: the `recherche-interne` skill. (Mission 152, ANOMALY 1 of report 151.)
