# DECISION — Seven session arbitrations of 2026-08-23

## Date

2026-08-23

## Status

`ARBITRATED`

Arbitration: Owner/Pilot session of 2026-08-23.

## Decision

Adoption of the seven arbitrations given by the Owner in session on 2026-08-23, as recorded in the proposal of the seven arbitrations and the revised batch order (workshop history, not distributed), §2.

1. **Locating the Vault from a project folder.** Retained: an upward-searched marker, a file placed at the working root, found by walking up the parent folders until it is found — the same principle as detecting a Git repository through `.git`. The written declaration remains as a reading convenience, not as the real mechanism. Set aside: proximity (`../vault/`), which breaks as soon as the user organizes their projects differently; the written declaration as the real mechanism, which demands manual maintenance per project.

2. **Content of the state sheet read at opening.** Retained: medium level — current state in one sentence, next action, open doors, catalogue of recent documents (path plus one line of description), state of the repositories. The sheet is a catalogue, not a summary, and copies neither Decisions nor rules. It is generated by script, never written by hand. Set aside: a level that would copy the content of the Decisions or rules, contrary to the catalogue principle.

3. **Classification of the activity.** Retained: the AI classifies and announces it in one short line, correctable with one word by the Owner. Classifying is not filing: any filing of a file remains a door announced before writing. Set aside: silent classification; confirmation asked before proceeding; automatic filing for reversible types.

4. **Keeping the state and closing the session.** Retained: state kept continuously and produced by script, pattern of the append-only journal with a derived view — the Pilot adds a line to the journal at each milestone, never writes the state sheet; the sheet is the regenerated view of the journal; a session stopped without a resume note is flagged without reconstructing anything. Technical constraint measured during the session: no script runs without a call from the agent in a chat window, and closing a tab triggers nothing — full delegation to the script is only possible on the Executor side. Set aside: full delegation to the script on the chat side, technically impossible under the measured conditions.

5. **Identity of the Vault.** Retained: name ("Brian") plus role contract, without personality, engraved in the marker file of the working root defined in point 1. Explicitly set aside: personality (voice, tone, manner of answering) — it has to be paid for again at every turn, and pushes the agent to answer "as Brian" fluently and confidently even when the file has not been read, which is what the evidence doctrine exists to prevent.

6. **Evaluation of Graphify.** Retained: correct, test, then decide — Graphify is neither frozen nor withdrawn in advance; it is repaired (the generated indexes do not enter the graph, the main defect to correct) and re-measured under the corrected conditions, full protocol in proposal 122144 §3. Set aside: freezing or withdrawing Graphify in advance, before measurement under the corrected conditions.

7. **Distribution and first installation.** Retained: a skeleton package plus a removable model project, erasable with one command — the model project is the business case « Une semaine sans écran » ["A week without screens"], rebuilt cleanly from the current templates. The project's real history is not installed at the user's: it becomes a system case study (the workshop built the workshop), intended for the presentation and the product sheet. The first-installation skill does four things and no more: ask its context questions, write the marker file with the name and the contract, start the journal, generate the first indexes. Set aside: installing the project's real history at the user's. *Amendment note (2026-08-26): the model project above is no longer « Une semaine sans écran » — Decision `205728` abandons this case study, and Decision `232341` (point 1.7) designates `wordpress-workshop` as the first-born of the project standard and candidate model project of the distributable package.*

## Reason

These seven points had been pending since the proposal of 2026-08-23 01:38 (workshop history, not distributed), replaced by proposal 122144. The Owner gave all of them in session on 2026-08-23; this Decision engraves them without waiting for the execution of the batches that follow from them.

## Impact

Opens the execution of batches A to E listed in proposal 122144 §5, starting with batch A (Mission 027). Serves as the normative foundation for any script or template that implements the journal, the state sheet, the classification, the identity of the Vault, the Graphify measurement protocol, and the distribution package.

## Important alternatives

- Full delegation to the script on the chat side: rejected, technically impossible in a chat window (measured during the session).
- Personality of the Vault in addition to the role contract: rejected, repeated rereading cost and risk of a confident answer without reading.
- Early freezing or withdrawal of Graphify: rejected, measurement must precede the verdict.
- Installing the project's real history at the user's: rejected, only the regenerated case study is distributed.
