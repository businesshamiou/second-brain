# DECISION — EXISTENCE SWEEP, MEMORY AND HYPOTHESES, « EXISTANT MESURÉ » RUBRIC

## Date

2026-09-04

## Status

`ARBITRATED`

Owner arbitration in plain words, Pilot session of 2026-09-04 (night), gate « grave » ["engrave"], after analysis of a blind spot measured in the same session.

## Triggering fact

Asked how a chat session reaches the Vault, the Pilot recommended creating a single entry file at the root of the Vault. The Owner arbitrated « go ». The template reading rule then led the Pilot to list the root of the Vault: `CLAUDE.md` was there, already carrying the exact entry line (« avant toute action, détermine ton rôle, lis la charte » ["before any action, determine your role, read the charter"]), alongside `AGENTS.md`, `README.md`, `INSTALL.md`, `USER.md` and `index.md`. The recommendation was a duplicate. A single listing call, before the recommendation, would have avoided it.

The same turn showed that the mechanism sought also existed: `VAULT-ROOT.md` at the root of the workspace, generated by `tools/write-marker.sh`, carries the relative path of the Vault; the root of the workspace is asked of the MCP server. No path needs to be fixed outside the repository.

## Decision

1. **Existence sweep before any creation recommendation.** Every answer of the Pilot that recommends creating a file, a tool, a skill or a mechanism carries, in the same answer and before the recommendation, the result of a sweep: the destination folder listed, and the intended function searched for in the Vault's indexes or by `tools/find-in-vault.sh`. Without a sweep shown, the recommendation is not issued and no arbitration is requested. The cost is one to two calls; the cost of the omission is an Owner arbitration rendered on a false basis.

2. **Memory is never a source of hypothesis.** The existing rule — the model's memory is never a source of state — read as a prohibition on *citing* memory. It extends explicitly to tacit use: the picture an agent has of the Vault's content, inherited from past sessions or from a summary, grounds neither a recommendation, nor a design, nor the decision not to check. Not asking oneself whether a file exists is a form of assertion.

3. **« Existant mesuré » (measured existing) rubric in the Mission template.** Every Mission whose Scope includes the creation of a file carries an « Existant mesuré » rubric: listing or search command played, output, and explicit conclusion (« aucun fichier ne remplit cette fonction » ["no file fulfils this function"] or « le fichier X la remplit partiellement, la Mission l'amende au lieu de créer » ["file X partly fulfils it, the Mission amends it instead of creating"]). A guardian refuses at commit a Mission that creates without this rubric filled in. The creation is detected by the presence, in the Scope, of a path absent from the repository.

## Reason

- The seven guardians, the reports' output contract and the challenge before issuing all bear on **committed artefacts**. The Pilot's chat prose has no check — yet it is exactly the medium on which the Owner arbitrates. The only unguarded artefact of the system is the one that triggers all the decisions.
- The challenge before issuing, instituted the same night, did find the duplicate — but downstream of the arbitration, and as a side effect of another rule. A check that only comes into play after the Owner's decision protects the execution, not the decision.
- The doctrine "measure before asserting" bore on verifiable states. A proposed design is not a state; it therefore escaped the rule while committing more.

## Impact

- The template `templates/mission-template.md` receives the rubric; existing Missions are not retroactively amended.
- A guardian remains to be written; as long as it does not exist, point 3 is doctrinal — and therefore, by this project's repeated finding, subject to drift. It joins the queue of Mission 132 "guardians contract".
- Points 1 and 2 are mechanizable by no guardian: nothing reads the chat. They are accepted as doctrinal and recorded in the checklist of the `écriture-de-mission` skill.
- First case of application: the Mission that adds to `CLAUDE.md` and `AGENTS.md` the two universal rules currently outside the repository (memory never a source of state; without MCP, ask for the files and produce nothing), instead of creating a new entry file.

## Important alternatives

- A guardian that would analyse the Pilot's answers: rejected, nothing reads the chat; the constraint would be doctrinal in a mechanical disguise.
- Widen the challenge before issuing to every recommendation: rejected as the sole remedy — it comes into play after the Owner's arbitration; it remains useful downstream, it does not replace the sweep upstream.
- Engrave nothing and record the fault in the checklist: rejected, the cause is structural and not an isolated slip.
