# COMMANDS

Generated by `tools/sb/sb.py generate` from `tools/sb/verbs.json` and the `sb.*` keys of the i18n catalogues. Do not edit by hand. The rule behind it: [the sb command surface](../../rules/RULES-2026-09-26-200933-sb-command-surface.md).

## Grammar

`sb <verb> [arguments]` in any terminal; `/sb:<verb>` in Claude Code (plugin `sb`); `$sb <verb>` in Codex; a message that starts with `sb ` to the Pilot or to any other agent. `sb help` shows the welcome screen, `sb help start` the first steps, `sb help <verb>` one page, `sb --version` the version.

**For an agent that receives `sb <verb>`:** with a shell, run `sb <verb> <arguments>` (if `sb` is not on the `PATH`: `bash <Vault>/tools/sb/bin/sb` in a POSIX shell such as Git Bash, `& "<Vault>\tools\sb\bin\sb.cmd"` in PowerShell, the Vault being named by the `VAULT-ROOT.md` marker found walking up), show its output as it is, then apply the verb's card below. Exit 3 means wrong place: say where the verb runs, and stop. **Without a shell (the Pilot):** apply the card of a verb marked *Pilot: yes*; for any other verb, answer that it needs a shell and must be typed in an Executor window.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | done (or the card of an agent verb shown) |
| 1 | the underlying tool refused or failed; its own message is shown as is |
| 2 | usage: unknown verb, missing or extra argument |
| 3 | wrong place: the refusal names where the verb runs |
| 4 | not allowed here: an Owner-only verb outside the laboratory |

### sb open

Open a work session and get the READY / NOT-READY verdict

- **Usage:** `sb open`
- **Runs:** inside an adopted project, or in the Vault (`project-or-vault`) · measured in the terminal, completed by your agent
- **Surfaces:** `sb open` · `/sb:open` · `$sb open` · Pilot: no — needs a shell

**Card (what the agent does).** Apply the session-start skill (skills/session-start/SKILL.md) from its section 0, the entry-scenario matrix: the output of `sb open` is the measurement of your branch; the first line of your answer is the verdict, READY or NOT-READY (<reason>), with nothing before it. - **Surfaces:** `sb push` · `/sb:push` · `$sb push` · Pilot: no — needs a shell
- **Built on:** [`tools/verified-push.sh`](../../tools/verified-push.sh), [`docs/how-to/delegate-and-push.md`](../how-to/delegate-and-push.md)
- **Also recognised:** « pousse », « push »
- **Next:** `sb status`

**What it does.** Pushes what your branch has beyond its remote through the verified push: path, current commit, remote head and history checked first.

**What it does not do.** It never forces. An agent pushes only on your delegation, named in its window.

**Examples.**

```text
sb push --dry-run   # see what would go
sb push   # push the current repository
sb push C:/Users/you/Workspaces/vault a1b2c3d..e4f5a6b   # a named range
```

**Card (what the agent does).** A push is the Owner's gesture. An Executor runs it only when the Owner delegated that push in this window by a clear expression naming the repository; otherwise it prints the command for the Owner. Never force.

### sb search

- **Next:** `sb help <verb>`

**Card (what the agent does).** Apply the internal-search skill (skills/internal-search/SKILL.md): indexes and descriptions first, then the exact search `sb search` ran; never assert a path you did not measure. Pilot: the same discipline through the MCP server's search, since this verb needs a shell.

### sb doctor

Check everything, and explain a refusal

- **Usage:** `sb doctor` · `sb doctor "<refusal message>"`
- **Runs:** anywhere inside your workspace (`workspace`) · done in the terminal
- **Surfaces:** `sb doctor` · `/sb:doctor` · `$sb doctor` · Pilot: no — needs a shell
- **Built on:** [`tools/check-workspace-root.sh`](../../tools/check-workspace-root.sh), [`tools/check-project-conformity.sh`](../../tools/check-project-conformity.sh), [`tools/project-bootstrap.sh`](../../tools/project-bootstrap.sh) identity --check, [`docs/how-to/react-to-a-guardian-refusal.md`](../how-to/react-to-a-guardian-refusal.md), [`docs/how-to/troubleshoot.md`](../how-to/troubleshoot.md)
- **Also recognised:** « diagnostic », « ça ne marche pas », « vérifie tout », « what is wrong »
- **Next:** `sb clean` · `sb install --path`

**What it does.** Checks sb on the PATH, Git and uv, bash under Windows, the workspace root, the Vault's guardians and tree, the Codex budget and its margin, the MCP server in every host present, the Claude Code plugin; in a project, its identity, conformity and links. Given a refusal message, finds its cause and fix in the guides.

**What it does not do.** It repairs nothing: each problem comes with the command that fixes it.

**Examples.**

```text
sb doctor   # the full checkup
sb doctor "preflight absent"   # what does this refusal mean?
```

**Card (what the agent does).** Show the output as it is; for each FAIL or WARN, give the fix it names and nothing else. Under Windows, a WARN on bash means only that `bash` is not on the PATH of that terminal: give the form it names, never install anything. The `MCP · <host>` lines say, for each host present, whether the Vault's server is declared there; a missing one is `sb install --mcp`, on the Owner's word. Never repair on your own: a repair is a Mission or the Owner's gesture.

### sb clean

What clutters the workspace, and where it should go

- **Usage:** `sb clean` · `sb clean --purge-temp [--yes]`
- **Runs:** anywhere inside your workspace (`workspace`) · done in the terminal
- **Surfaces:** `sb clean` · `/sb:clean` · `$sb clean` · Pilot: no — needs a shell

- **Also recognised:** « range », « nettoie », « tidy up »
- **Next:** `sb doctor`

**What it does.** Lists what the workspace root holds beyond its allowed list, and measures the declared temporary folder and the trash. With --purge-temp, empties the temporary folder after your confirmation (--yes to skip the question).

**What it does not do.** It never touches _trash nor _archive, and moves nothing. Emptying the temporary folder is your gesture: it happens only when you ask for it.

**Examples.**

```text
sb clean   # anywhere in the workspace
sb clean --purge-temp   # empty the temporary folder, after a question
```

**Card (what the agent does).** Show the output as it is. It never touches _trash nor _archive. `--purge-temp` deletes the declared temporary folder's content for good: the Owner's gesture, run only on the Owner's word in this window, never on an agent's initiative.

### sb install

Install, repair, put sb on the PATH

- **Usage:** `sb install` · `sb install --path` · `sb install --plugin` · `sb install --mcp [--label <label>]` · `sb install --run`
- **Runs:** anywhere (`anywhere`) · done in the terminal
- **Surfaces:** `sb install` · `/sb:install` · `$sb install` · Pilot: no — needs a shell
- **Built on:** [skill `first-install`](../../skills/first-install/SKILL.md), [`install.ps1`](../../install.ps1), [`install.sh`](../../install.sh), [`tools/install-vault-mcp.sh`](../../tools/install-vault-mcp.sh), [`tools/lib/mcp-hosts.sh`](../../tools/lib/mcp-hosts.sh), [`docs/tutorials/install.md`](../tutorials/install.md), [`docs/how-to/pilot-hosts-and-role-mixing.md`](../how-to/pilot-hosts-and-role-mixing.md)
- **Also recognised:** « installe Second Brain », « install Second Brain »
- **Next:** `sb doctor` · `sb help start`

**What it does.** Runs the installation's last steps, in order, each one only if needed: 1. puts sb on your user PATH; 2. adds the Claude Code marketplace second-brain; 3. installs the plugin sb, so that /sb:<verb> exists; 4. declares the Vault's MCP server in every tool present — the Claude app, Claude Code, Codex,    Gemini CLI, Cursor, Windsurf, Cline, LM Studio (the Pilot's access to your files);    --mcp --label <label> gives it a shorter name. --path, --plugin or --mcp runs one step alone; --run resumes or repairs the installation.

**What it does not do.** It writes nothing into your profile but the PATH entry and Claude Code's own plugin settings, the two things you ask it for.

**Examples.**

```text
sb install   # the three steps, each one if needed
sb install --plugin   # only the Claude Code plugin
sb install --run   # resume or repair the installation
sb install --mcp --label acme   # the server under a shorter name
```

**Card (what the agent does).** Show the output as it is. `sb install` writes one entry into the user's PATH, Claude Code's plugin settings (marketplace second-brain, plugin sb) and the Vault's MCP server into every host present (Claude desktop app, Claude Code, Codex, Gemini CLI, Cursor, Windsurf, Cline, LM Studio): run it only on the Owner's word. A name too long for the hosts is refused with a shorter label proposed: `sb install --mcp --label <label>`, on the Owner's choice. For a first installation or a repair driven from the chat, apply the first-install skill (skills/first-install/SKILL.md).
